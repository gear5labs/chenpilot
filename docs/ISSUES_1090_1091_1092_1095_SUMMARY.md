# Planner Fallbacks, Policy Rationales, Diagnostic Traces & Idempotency (#1090, #1091, #1092, #1095)

## Overview
This document specifies hardening measures for ChenPilot's Agent Planner across invalid output fallbacks, actionable policy denial rationales, support trace redaction, and duplicate tool invocation prevention.

---

### 1. Deterministic Fallback on Invalid Planner Output (#1090)
- **Problem**: Incomplete or malformed JSON from language models could trigger accidental partial execution or unhandled runtime crashes.
- **Solution**: `handleInvalidPlannerOutputFallback` halts execution, returns structured non-executable error metadata, and manages retry boundaries.

---

### 2. User-Visible Rationale for Denied Execution Plans (#1091)
- **Problem**: When transactions were denied by security or risk policies, internal error codes or risk model names were exposed to end users.
- **Solution**: `getSanitizedDenialRationale` provides actionable user guidance without leaking internal system policy specifics.

---

### 3. Bounded Planner Support Traces (#1092)
- **Problem**: Customer support troubleshooting required decision logs, but raw prompts contained PII and signing keys.
- **Solution**: `exportBoundedSupportTrace` redacts sensitive argument payloads while preserving decision classes and tool call sequences.

---

### 4. Idempotent Tool Execution (#1095)
- **Problem**: Network retries or repeated planner steps risked duplicate on-chain executions.
- **Solution**: `IdempotentToolExecutionManager` caches outcomes by idempotency key and rejects conflicting payloads for the same transaction key.
