# CSV Export Contract & Formula Sanitization Specification

## Overview

This document specifies the export contract for all CSV data generated by the Chenpilot platform (including operator reports, audit log exports, transaction history, and user profile dumps).

Spreadsheet applications (such as Microsoft Excel, Google Sheets, Apple Numbers, and LibreOffice Calc) interpret certain character patterns as executable formulas or DDE macro commands. To prevent **CSV / Formula Injection (CWE-1236)** and ensure cross-platform interoperability, all CSV generators MUST conform to this contract.

---

## 1. Formula Prefix Defense (CWE-1236)

### 1.1 Trigger Characters
Spreadsheets evaluate an unquoted or quoted cell as a dynamic formula if the trimmed text begins with any of the following characters:
- Equals sign: `=`
- Plus sign: `+`
- Hyphen-minus: `-`
- At symbol: `@`
- Horizontal tab: `\t` (`0x09`)
- Carriage return: `\r` (`0x0D`)
- Pipe character: `|` (often used in DDE execution strings)
- Percent symbol: `%` (used in certain spreadsheet query macros)

### 1.2 Neutralization Rule
When a field's trimmed string value starts with any trigger character:
1. Prepend an apostrophe (`'`).
2. Enclose the resulting cell in double quotes (`"`).
3. The leading apostrophe forces spreadsheets to display the text literally without evaluating formulas or executing external commands.

**Example Transformation**:
| Raw Input | Escaped Output |
| :--- | :--- |
| `=SUM(A1:B10)` | `"'=SUM(A1:B10)"` |
| `+cmd|' /C calc'!A0` | `"'+cmd|' /C calc'!A0"` |
| `@HYPERLINK("https://evil.com")` | `"'@HYPERLINK(""https://evil.com"")"` |
| `-500 XLM` | `"'-500 XLM"` |
| `   =1+1` (leading whitespace) | `"'   =1+1"` |

## 2. Control Character & BiDi Sanitization

### 2.1 Non-Printable ASCII Controls
Non-printable ASCII control characters (`\u0000-\u0008`, `\u000B\u000C`, `\u000E-\u001F`, `\u007F-\u009F`) can break CSV parsers, cause truncated records, or hide malicious payloads.
- **Rule**: All non-printable ASCII control characters are stripped prior to escaping.

### 2.2 BiDi (Bidirectional) Override Characters
Unicode directional formatting characters (`\u202A-\u202E`, `\u2066-\u2069`) can visually reverse text strings in RTL-capable viewers (e.g. reversing account addresses or disguising dangerous formula names).
- **Rule**: All BiDi override characters are removed during sanitization.

---

## 3. RFC 4180 Compliance

All generated CSV output conforms to RFC 4180 standards:

1. **Delimiters & Quoting**:
   - Fields are delimited by a single comma (`,`).
   - Fields containing a comma (`,`), double quote (`"`), newline (`\n` or `\r`), leading/trailing whitespace, or formula prefix escapes MUST be wrapped in double quotes.
2. **Escaping Internal Quotes**:
   - Any literal double quote (`"`) inside a cell is escaped by doubling it (`""`).
3. **Record Termination**:
   - Each record is terminated by a standard CRLF (`\r\n`) sequence.
4. **Header Row**:
   - The first row MUST contain canonical column headers describing the record fields.

---

## 4. Unicode & Internationalization

- All exports use UTF-8 character encoding.
- International text (including Chinese, Japanese, Cyrillic, Arabic, Hebrew, Latin accents, and Unicode emojis) is preserved without loss or truncation.
- Safe Unicode characters are never converted to question marks or lossy ASCII equivalents.
