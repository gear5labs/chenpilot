# Portfolio Valuation, Staleness Transparency & Diagnostic Redaction (#1096, #1097, #1098, #1099)

## Overview
This document specifies improvements to portfolio aggregation reliability, explicit staleness detection, missing price disclosures, canonical asset export formatting, and diagnostic prompt redaction.

---

### 1. Planner Prompt Redaction Policy (#1096)
- **Problem**: Diagnostic logs in production could inadvertently persist sensitive API keys, private signing seeds, or user credentials.
- **Solution**: `redactPlannerPromptDiagnostics` automatically redacts Stellar private keys (`S...`), EVM private keys (`0x...`), Bearer authorization headers, and token secrets in production environments.

---

### 2. Explicit Price Staleness Indicators (#1097)
- **Problem**: Portfolio summaries presented valuation numbers without indicating whether the underlying oracle price feeds were outdated.
- **Solution**: Attached explicit timestamp and `isStale` flag to each position valuation, reporting `staleAssetsCount` in overall portfolio summaries.

---

### 3. Valuation Behavior for Unpriced Assets (#1098)
- **Problem**: Partial portfolio valuations risked silently assuming zero value for missing prices or omitting unpriced tokens without explanation.
- **Solution**: Added `completenessStatus` (`COMPLETE` | `PARTIAL` | `UNPRICED`), `completenessRatio`, and an explicit `unpricedAssets` list distinguishing unknown valuations from zero-value assets.

---

### 4. Canonical Asset Identity Preservation (#1099)
- **Problem**: Exporting portfolios using symbol-only fields caused ambiguity between distinct tokens sharing the same symbol across different issuers or networks.
- **Solution**: `exportPortfolioCanonical` guarantees `network` and `issuerOrContract` addresses accompany asset symbols across both structured JSON and CSV export formats.
